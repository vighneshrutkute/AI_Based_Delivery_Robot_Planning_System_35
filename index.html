About the AI Delivery Robot Planning System

Comprehensive architectural specification, state space formalization, and algorithmic proofs for engineering review.

1. Formal Problem Formulation

The autonomous robot delivery task is formalized as a classical deterministic planning problem under the tuple $\mathcal{P} = \langle \mathcal{S}, \mathcal{A}, \mathcal{T}, \mathcal{S}_0, \mathcal{G}, \mathcal{C} \rangle$:

  • State Space $\mathcal{S}$: Represented by the 6-tuple: $$\mathcal{S} = \langle (x_r, y_r), \text{has\_cargo}, (x_p, y_p), (x_d, y_d), \text{delivered}, \text{battery} \rangle$$ where $0 \le x_r, x_p, x_d < W$ and $0 \le y_r, y_p, y_d < H$.
  • Initial State $\mathcal{S}_0$: $$\mathcal{S}_0 = \langle (x_0, y_0), \text{false}, (x_p, y_p), (x_d, y_d), \text{false}, 100\% \rangle$$
  • Goal Condition $\mathcal{G}$: $$\mathcal{G} \equiv \big((x_r = x_d \land y_r = y_d) \land (\text{delivered} = \text{true}) \land (\text{has\_cargo} = \text{false})\big)$$
2. STRIPS / PDDL Action Schema
Action: MOVE($(x, y)$, $(x', y')$)
Preconditions: At(Robot, $(x, y)$) ∧ Adjacent($(x, y)$, $(x', y')$) ∧ ¬Obstacle($(x', y')$)
Effects: ¬At(Robot, $(x, y)$) ∧ At(Robot, $(x', y')$)
Cost: $c(x', y') = \text{base\_cost} \times \text{terrain\_weight}(x', y')$
Action: PICKUP(Item, $(x_p, y_p)$)
Preconditions: At(Robot, $(x_p, y_p)$) ∧ At(Item, $(x_p, y_p)$) ∧ ¬Holding(Robot, Item)
Effects: Holding(Robot, Item) ∧ ¬At(Item, $(x_p, y_p)$)
Action: DROPOFF(Item, $(x_d, y_d)$)
Preconditions: At(Robot, $(x_d, y_d)$) ∧ Holding(Robot, Item)
Effects: ¬Holding(Robot, Item) ∧ Delivered(Item, $(x_d, y_d)$)
3. Heuristic Functions & Admissibility

For the $A^*$ search algorithm, the heuristic function $h(n)$ estimates the cost from node $n=(x, y)$ to the sub-goal $g=(x_g, y_g)$:

  • Manhattan Distance (4-Connected Grid): $$h_{\text{manhattan}}(n) = |x - x_g| + |y - y_g|$$ Proof of Admissibility: Since diagonal moves are forbidden, every path requires at least $|x - x_g|$ horizontal and $|y - y_g|$ vertical steps. Thus $h(n) \le h^*(n)$ always holds, guaranteeing optimality.
  • Diagonal / Octile Distance (8-Connected Grid): $$h_{\text{octile}}(n) = \min(\Delta x, \Delta y) \cdot \sqrt{2} + |\Delta x - \Delta y|$$
  • Dijkstra (Uniform Cost Search): $$h(n) = 0$$ Unbiased baseline that explores uniform cost contours.
4. Benchmark Scenarios Handled
  1. Normal Delivery: Complete plan with Phase 1 $\to$ Pickup $\to$ Phase 2 $\to$ Destination.
  2. Blocked Destination: Destination surrounded by obstacles. Planning terminates before execution and flags goal infeasibility.
  3. Unreachable Pickup Point: Pickup node closed off. Flags Phase 1 precondition failure.
  4. Item Already at Destination: Pickup equals destination ($x_p=x_d \land y_p=y_d$). System executes immediate localized pickup/dropoff with zero transit cost.
  5. Multiple Routes with Different Costs: A direct high-friction mud corridor (Cost = 3.5/step) versus a longer clean perimeter path (Cost = 1.0/step). Demonstrates intelligent cost minimization over pure physical distance.
  6. Invalid Task Specification: Input validation catches coordinates out of bounds, negative indexes, or missing item names with friendly diagnostics.
